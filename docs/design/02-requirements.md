# 요구사항 정의

본 문서는 재고관리 시스템 MVP가 제공해야 하는 기능과 업무 규칙을 정의한다.

---

## 1. 구현 범위

이번 MVP는 아래 범위까지만 구현한다.

### 포함

* 업체별 상품 구분
* 상품 입고
* 신규 상품 생성과 최초 입고
* 상품 출고
* 현재 재고 조회
* 동시 요청에 대한 재고 정합성 보장
* 잘못된 요청에 대한 오류 처리

### 제외

* 다건 입출고 (입고와 출고는 한 요청에 상품 하나만 처리한다)
* 재고 목록 조회
* 상품 검색
* 재고 변동 이력
* 창고/로케이션별 재고
* 예약 재고
* 외부 WMS/ERP 연동
* 대량 요청을 위한 메시지 큐
* 인증/인가 시스템
* 멱등성
* 상품 정보 변경
* 별도 상품 등록
* 업체 등록·관리

---

## 2. 시스템 목적

재고관리 시스템은 업체가 상품을 입고하고 출고할 수 있도록 하며, 상품별 현재 재고를 확인할 수 있어야 한다.

여러 요청이 동시에 발생하는 상황에서도 재고가 실제 상태와 다르게 관리되지 않도록 해야 한다.

특히 다음 상황에서도 재고의 정합성을 유지한다.

* 동일 상품에 여러 입고 요청이 동시에 발생하는 경우
* 동일 상품에 여러 출고 요청이 동시에 발생하는 경우
* 동일한 신규 상품에 여러 입고 요청이 동시에 발생하는 경우
* 입고와 출고가 동시에 발생하는 경우

---

## 3. 기본 업무 규칙

### 업체 구분

상품과 재고는 업체별로 구분하여 관리한다.

MVP에서는 요청에 포함된 `X-Tenant-Id`를 통해 업체를 식별한다.

업체는 미리 등록되어 있어야 한다.

`X-Tenant-Id`가 없거나, 비어 있거나, 등록되지 않은 업체면 요청을 처리하지 않는다.

업체는 자신의 상품에만 접근할 수 있다.

### 상품

상품은 상품코드와 상품명으로 관리한다.

상품코드는 업체 안에서 상품을 구분하는 값이며, 해당 업체 안에서 유일해야 한다.

서로 다른 업체는 같은 상품코드를 사용할 수 있다.

```text
업체 A / A001
업체 B / A001
```

위는 허용하고, 아래처럼 같은 업체에서 같은 상품코드를 여러 번 등록하는 것은 허용하지 않는다.

```text
업체 A / A001
업체 A / A001
```

상품코드는 영문 대소문자, 숫자, `_`, `-`로 이루어진 1~100자이며 대소문자를 구분한다.

상품명은 1~255자이며 비어 있거나 공백만 있을 수 없다.

상품코드와 상품명의 길이는 글자(문자) 단위로 센다. 이모지처럼 두 단위를 차지하는 글자도 한 글자다.

상품명은 대소문자와 공백까지 정확히 같을 때만 같은 상품명으로 본다.

상품의 현재 재고 수량은 상품 정보와 별도로 관리한다.

### 수량

입고 및 출고 수량은 1 이상의 정수여야 한다.

요청 한 건의 수량은 1,000,000,000을 넘을 수 없으며, 이 상한은 설정으로 관리한다.

0, 음수, 상한을 넘는 수량은 유효한 요청으로 취급하지 않는다.

소수나 문자열 같은 정수가 아닌 값도 유효한 요청으로 취급하지 않는다.

현재 재고는 음수가 될 수 없다.

### 요청 단위

하나의 입고 요청은 하나의 상품만 대상으로 한다.

하나의 출고 요청도 하나의 상품만 대상으로 한다.

내용이 같은 요청이 여러 번 들어와도 각각 독립된 요청으로 처리한다.

재시도로 같은 요청이 다시 오면 수량이 중복 반영될 수 있다.

요청 본문에 정의되지 않은 필드가 있으면 무시한다.

## 4. 상품 입고

### 기존 상품 입고

요청한 업체에 이미 등록된 상품이 입고되면 현재 재고에 입고 수량을 더한다.

예:

```text
현재 재고: 100
입고: 30

→ 최종 재고: 130
```

### 신규 상품 입고

요청한 업체에 등록되지 않은 상품코드가 입고되면 해당 업체의 신규 상품으로 등록한 후 입고를 처리한다.

다른 업체에 같은 상품코드가 있어도 요청한 업체에 없으면 신규 상품이다.

처리 결과는 다음과 같은 상태여야 한다.

```text
상품 등록 완료
+
입고 수량 반영 완료
```

상품만 등록되고 재고가 반영되지 않은 상태로 작업이 끝나서는 안 된다.

### 동일한 신규 상품의 동시 입고

아직 등록되지 않은 동일 상품에 같은 업체의 입고 요청이 동시에 발생할 수 있다.

예:

```text
A001 / +10
A001 / +20
A001 / +30
```

이 경우:

* 상품은 하나만 등록되어야 한다.
* 각 요청의 입고 수량은 모두 반영되어야 한다.
* 최종 재고는 60개가 되어야 한다.

먼저 등록된 상품이 기준이 되며, 나머지 요청은 기존 상품에 대한 입고로 처리한다.

* 나머지 요청의 상품명이 먼저 등록된 상품명과 다르면 상품명 불일치로 거부한다.
* 어느 요청이 먼저 등록될지는 보장하지 않는다.

### 기존 상품의 상품명 불일치

이미 등록된 상품코드에 대해 기존 상품명과 다른 상품명으로 입고를 요청할 수 없다.

예:

```text
기존 상품
A001 / Apple

입고 요청
A001 / Samsung / 10
```

위 요청은 거부한다.

입고 과정에서 기존 상품의 상품명을 변경하지 않는다.

### 동시 입고

동일 상품에 입고 요청이 동시에 발생하더라도 정상적으로 처리된 요청의 입고 수량이 누락되어서는 안 된다.

예:

```text
초기 재고: 0

+10
+20
+30

→ 최종 재고: 60
```

### 입고 결과

입고가 성공하면 이 요청이 반영된 직후의 재고 수량을 알려준다.

동시에 처리된 요청들은 서로 다른 재고 수량을 받을 수 있다.

## 5. 상품 출고

### 정상 출고

요청한 업체에 등록된 상품에 대해 출고 요청이 들어오면 출고 수량만큼 현재 재고를 감소시킨다.

예:

```text
현재 재고: 100
출고: 30

→ 최종 재고: 70
```

### 등록되지 않은 상품의 출고

등록되지 않은 상품은 출고할 수 없다.

다른 업체에만 있는 상품코드도 등록되지 않은 상품으로 본다.

상품을 찾을 수 없는 경우 출고하지 않는다.

### 재고 부족

현재 재고보다 많은 수량을 출고할 수 없다.

예:

```text
현재 재고: 10
출고 요청: 11

→ 출고 실패
→ 재고: 10 유지
```

부분적으로 가능한 수량만 출고하지 않는다.

### 동시 출고

동일 상품에 여러 출고 요청이 동시에 발생하더라도 실제 재고보다 많은 출고가 성공해서는 안 된다.

예:

```text
초기 재고: 10

요청 A: 10개 출고
요청 B: 10개 출고

→ 한 건만 성공
→ 한 건은 실패
→ 최종 재고: 0
```

### 입고와 출고 동시 발생

동일 상품에 입고와 출고가 동시에 발생할 수 있다.

각 요청은 실제 처리 결과에 따라 성공하거나 실패할 수 있으나, 최종적으로 재고가 음수가 되어서는 안 된다.

예:

```text
현재 재고: 10

입고: +10
출고: -15
```

입고가 먼저 커밋되면 출고가 성공할 수 있고, 출고가 먼저 처리되면 재고 부족으로 실패할 수 있다.

```text
출고 성공 → 최종 재고: 5
출고 실패 → 최종 재고: 20
```

어느 경우에도 허용되지 않는 재고 상태가 발생해서는 안 된다.

### 출고 결과

출고가 성공하면 이 요청이 반영된 직후의 재고 수량을 알려준다.

## 6. 재고 조회

### 현재 재고 조회

업체는 상품코드를 이용하여 자신의 상품에 대한 현재 재고를 확인할 수 있어야 한다.

조회 결과에는 다음 정보를 포함한다.

* 상품코드
* 상품명
* 현재 재고 수량
* 마지막 재고 변경 시각

상품은 상품코드로 식별하며, 시스템 내부 식별자는 응답에 노출하지 않는다.

### 존재하지 않는 상품 조회

등록되지 않은 상품을 조회하면 재고 정보를 반환하지 않고 상품이 존재하지 않음을 알린다.

다른 업체에만 있는 상품코드도 존재하지 않는 상품으로 본다.

### 조회 중 재고 변경

재고 조회와 입고 또는 출고가 동시에 발생할 수 있다.

조회는 재고 변경을 막지 않는다.

조회 결과가 반환된 이후 다른 요청으로 재고가 변경될 수 있으며, 이 상황은 정상적인 상태 변화로 본다.

---

## 7. 허용하지 않는 상태

시스템은 다음 상태를 허용하지 않는다.

### 상품

* 같은 업체 안에 동일 상품코드를 가진 상품이 여러 개 존재하는 상태

### 재고

* 하나의 상품에 여러 개의 현재 재고가 존재하는 상태
* 음수 재고가 존재하는 상태

### 입고

* 정상적으로 처리된 입고 수량이 최종 재고에 누락되는 상태
* 신규 상품만 생성되고 최초 입고가 반영되지 않은 상태

### 출고

* 현재 재고보다 많은 수량이 출고된 상태
* 동시 출고로 인해 재고가 음수가 된 상태

### 판정 기준

어떤 요청 조합에서도 다음 식이 성립해야 한다.

```text
최종 재고 = 초기 재고 + 성공한 입고 수량의 합 − 성공한 출고 수량의 합
```

실패한 요청은 상품과 재고에 아무것도 남기지 않는다.

## 8. 오류 처리 규칙

다음 상황에서는 요청을 정상 처리하지 않고 아래 응답을 반환한다.

오류 응답 본문은 에러 코드(`code`)와 메시지(`message`)를 담는다.

### 잘못된 요청

| 상황 | 응답 |
|---|---|
| Tenant 정보가 없거나, 비어 있거나, 등록되지 않음 | 400 `INVALID_TENANT` |
| 필수 정보가 누락됨 | 400 `INVALID_REQUEST` |
| 요청 형식이 올바르지 않음 (정수가 아닌 수량, 깨진 JSON 등) | 400 `INVALID_REQUEST` |
| 요청 본문의 상품코드가 허용 문자·길이를 벗어나거나, 상품명이 공백뿐이거나 최대 길이를 넘음 | 400 `INVALID_REQUEST` |
| 수량이 1 미만이거나 상한을 넘음 | 400 `INVALID_QUANTITY` |

### 상품 없음

| 상황 | 응답 |
|---|---|
| 요청한 업체에 없는 상품을 출고 | 404 `PRODUCT_NOT_FOUND` |
| 요청한 업체에 없는 상품의 재고를 조회 (경로의 상품코드가 형식에 맞지 않는 경우 포함) | 404 `PRODUCT_NOT_FOUND` |

### 상태 충돌

| 상황 | 응답 |
|---|---|
| 현재 재고보다 많은 수량을 출고 | 409 `INSUFFICIENT_STOCK` |
| 기존 상품과 다른 상품명으로 입고 | 409 `PRODUCT_NAME_MISMATCH` |

### 그 밖의 오류

| 상황 | 응답 |
|---|---|
| 존재하지 않는 경로 | 404 `RESOURCE_NOT_FOUND` |
| 지원하지 않는 HTTP 메서드 | 405 `METHOD_NOT_ALLOWED` |
| 예상하지 못한 서버 오류 (DB 동시성 오류 포함) | 500 `INTERNAL_SERVER_ERROR` |

500 응답에는 내부 처리 내용을 노출하지 않으며, 요청은 반영되지 않는다.

### 여러 오류가 겹치는 경우

한 요청에 여러 오류가 있으면 다음 순서로 먼저 걸리는 오류 하나만 반환한다.

```text
1. Tenant 확인
2. 요청 형식
3. 필수값 · 길이
4. 수량 범위
5. 상품 존재
6. 상품 · 재고 상태
```

경로 · 메서드 오류는 위 순서와 별개로 이렇게 판정한다.

- 지원하지 않는 HTTP 메서드(405 `METHOD_NOT_ALLOWED`)는 Tenant 확인보다 먼저 판정한다
- 존재하지 않는 경로(404 `RESOURCE_NOT_FOUND`)는 Tenant 확인 뒤에 판정한다. 헤더가 없으면 400 `INVALID_TENANT`다
